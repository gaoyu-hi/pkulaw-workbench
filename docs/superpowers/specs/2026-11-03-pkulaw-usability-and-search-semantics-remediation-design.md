# 北大法宝工作台可用性与检索语义修正设计

**日期：** 2026-11-03  
**状态：** 需求已确认，等待实施计划执行批准  
**基线：** `f650e06`  
**范围：** 检索字段与匹配语义、采集表单布局、年份起点、暂停详情与操作反馈、
验证码自动恢复、总览入口按钮

## 1. 目标

修正当前已验证版本中会直接影响检索结果和日常操作的一组问题：

1. “关键词”不能再错误地使用北大法宝全文检索。
2. 新建任务的检索框不得带任何产品预设文字。
3. 采集表单必须在不依赖外层滚动的情况下始终露出主操作按钮。
4. 年份模式与省份改为两行，年份区间切换后保持稳定布局。
5. 总览三个采集入口按钮尺寸和视觉权重一致。
6. 年份起点应适配当前检索实际可用的最早年份。
7. 暂停时所有原因、操作结果和当前唯一有效动作必须可见。
8. 人工完成滑块后，应尽量自动恢复，不能反复要求“已处理，继续”。

程序不得自动破解、模拟或绕过验证码。修正的目标是减少误判和多余点击，
不是绕过网站访问控制。

## 2. 检索模式

### 2.1 单篇

提供三个匹配方式：

| 界面名称 | 内部模式 | 北大法宝字段 | 匹配类型 | 同名政策处理 |
|---|---|---|---|---|
| 关键词 | `keyword` | `SearchKeywordType=Title` | `MatchType=Exact` | 按稳定政策 ID 分别保留 |
| 全文 | `fulltext` | `SearchKeywordType=FullText` | `MatchType=Exact` | 按稳定政策 ID 分别保留 |
| 精确完整标题 | `title` | `SearchKeywordType=Title` | `MatchType=Exact` | 同名候选进入人工选择 |

“关键词”和“精确完整标题”在网站上的字段及匹配类型相同，区别只在后续同名
政策身份处理。

### 2.2 批量

批量保留：

- 关键词：`Title + Exact`
- 全文：`FullText + Exact`

“精确完整标题”仍只适用于逐篇任务。批量不得使用模糊匹配。

### 2.3 强制核验

提交检索前和页面稳定后都必须核验：

- `SearchKeywordType` 与实际字段一致；
- `MatchType=Exact`；
- 页面没有自动回退到模糊匹配；
- 搜索 URL/表单参数和页面可见条件同时一致。

任何一项不一致都失败关闭并显示明确错误，不得静默改用另一字段。

### 2.4 旧任务兼容

发布修正前创建的 `matchMode=keyword` 任务曾按 FullText 执行。新版本不能让这些
任务在未提示的情况下按 Title 含义继续。

- 新任务写入 `searchSemanticsVersion=2`。
- 配置指纹包含该版本。
- 无版本旧任务仍可在任务中心查看，但在恢复扫描前必须重新应用任务设置。
- 旧任务恢复被拒绝时返回 `SEARCH_SEMANTICS_UPGRADE_REQUIRED`，不得复用旧
  scanJournal。
- 用户在任务设置中明确选择新模式后，沿用同一 taskId、递增配置版本并清空旧
  扫描派生状态；已完成文件继续保留。

## 3. 新建任务默认值

- 新建逐篇、批量任务时，检索文本框初始为空。
- 不得自动填入“人工智能”、示例短语或测试值。
- 检索文本框不使用示例占位文字；`value` 和 `placeholder` 都保持空。
- 产品默认值与用户主动保存的草稿必须可区分。
- 迁移旧本地草稿时，只清理已知产品默认值；其他用户输入保留。

## 4. 表单布局

### 4.1 顶部文案

逐篇和批量创建表单顶部不再重复当前导航模式，也不显示两段长说明。
必要安全提示压缩为一行短文案。

### 4.2 字段布局

年份模式单独占一整行，省份单独占下一整行，不再并列。

年份区间模式中：

- 年份模式、起始年份、结束年份在稳定网格内显示；
- 切换模式不得把省份挤到不自然的位置；
- 年份输入继续支持手动输入 1949–当前年份。

### 4.3 主操作

“创建并开始逐篇采集”“创建并开始批量采集”“应用设置”必须始终位于创建或
设置面板的可视区域底部。

- 不恢复外层页面滚动；
- 主操作使用面板内固定或粘性操作栏；
- 表单主体通过紧凑布局控制高度；
- 极矮窗口也不得隐藏主操作。

## 5. 总览采集入口

“进入逐篇采集”“进入批量采集”“运行环境诊断”三个按钮：

- 使用相同高度、宽度和排列基线；
- 使用一致的按钮视觉权重；
- 在支持的宽屏和窄屏基准下都不出现一大两小；
- 不只靠文字长度决定宽高。

## 6. 年份起点

年份范围请求早于当前检索实际可用年份时，不应直接以
`YEAR_FILTER_UNAVAILABLE` 暂停。

执行逻辑：

1. 读取当前检索范围可用的年份树/年份值。
2. 计算最早有效年份。
3. 区间模式将起始年份提升到 `max(用户起始年份, 最早有效年份)`。
4. 结束年份不得超过可用年份上限。
5. 把有效年份范围和原始请求写入 checkpoint，避免审计丢失。
6. 界面显示程序实际使用的起始年份。

以下情况仍失败关闭：

- 年份树不存在；
- 可用年份为空；
- 指定单一年份不存在；
- 无法证明年份筛选已生效。

## 7. 暂停详情与任务动作

### 7.1 详情可读性

暂停卡片不得因固定高度裁掉原因。使用以下任一方式保证完整信息可读：

- 紧凑摘要加“查看完整原因”弹窗；
- 仅任务面板内部受控滚动。

优先使用弹窗，保持“外层不滚动”的既有约束。暂停详情弹窗必须包含：

- 错误代码；
- 完整原因；
- 当前检索组合、页码和断点；
- 可用年份或候选值；
- 建议动作；
- 原始错误详情。

### 7.2 唯一有效动作

同一时刻只显示当前有效的一个继续类主动作：

- 工作线程仍存活且等待人工继续：`已处理，继续`
- 工作线程已退出但断点可续：`从断点继续扫描`
- 自动恢复失败但任务仍等待：`重新检测并继续`

任何动作点击后都必须在 1 秒内显示“正在处理”，并在结束前显示成功或失败。
静默无反馈不可接受。

### 7.3 错误分类

`YEAR_FILTER_UNAVAILABLE` 不是普通人工登录门禁。年份可自动归一化时自动处理；
否则进入明确的年份决策/修复状态，不显示普通“已处理，继续”。

## 8. 验证码恢复

### 8.1 保留原 Py 的可靠行为

- 保持同一个已认证浏览器 Session；
- 不因一次自动复核失败就结束任务工作线程；
- 人工处理期间无限期等待；
- 完成后优先自动恢复；
- 人工“继续”仅作为兜底，不作为正常必经步骤。

### 8.2 清除检测

自动恢复不能只靠短时间两次采样：

- 至少 3 次稳定清除样本；
- 样本覆盖约 2–3 秒；
- 任意一次重新出现滑块、登录页或页面跳转即清零；
- 用户完成滑块后，若站点的覆盖层短暂残留，继续观察而不是立即判定失败；
- 连续失败达到明确阈值后，才显示“重新检测并继续”。

`CAPTCHA_VISIBLE` 自动复核失败时：

- 不清除任务检查点；
- 不停止后台线程；
- 不显示第二个普通继续按钮；
- 回到稳定观察或单一兜底状态。

### 8.3 按钮语义

- `重新检测并继续`：仅重新开始稳定检测，不立即强制通过。
- `已处理，继续`：仅在工作线程仍活着且确实处于可恢复人工门禁时出现。
- `从断点继续扫描`：仅在工作线程已退出且存在可信断点时出现。

## 9. 错误反馈

所有任务操作必须立即显示：

- 已提交；
- 处理中；
- 成功；
- 失败原因。

失败原因不能只放在面板底部被裁掉的位置。顶部状态区、操作按钮附近或固定通知
区域至少一处必须可见。

## 10. 验收基准

### 10.1 检索语义

- 选择“关键词”，北大法宝显示标题字段和精确匹配；
- 选择“全文”，北大法宝显示全文字段和精确匹配；
- 选择“精确完整标题”，北大法宝显示标题字段和精确匹配，并保留候选消歧；
- 任何模式出现 Fuzzy 时停止且无下载。

### 10.2 布局

- 1536×864 逻辑视口，外层 `scrollHeight <= innerHeight + 1`；
- 新建单篇、批量表单的主按钮始终可见；
- 年份模式和省份分两行；
- 总览三个入口按钮尺寸一致；
- 暂停详情可完整打开阅读。

### 10.3 回归

- Python、Vitest、TypeScript 全绿；
- Stage 6 夹具烟测覆盖三种检索模式、动态年份起点、按钮唯一性、暂停详情和
  验证码自动恢复；
- 便携包首次启动、一键启动和强制退出恢复通过。

## 11. 非目标

- 不自动破解、识别或绕过验证码；
- 不自动输入账号密码；
- 不导出或共享 Cookie；
- 不增加 WPS、PDF、纯文本、超文本、纯净版下载格式；
- 不增加三个法宝联想保留选项；
- 不改变数据处理的来源和完整性规则；
- 不在本轮加入 macOS 适配。
