# 任务完成复位与设置修订设计

- **状态**：已确认设计
- **范围**：Windows 逐篇采集、批量采集、任务设置、任务成果文件处理
- **依赖**：当前 Windows 分支上的自适应检索与任务边界实现

## 1. 背景

当前存在两个相互关联的界面状态问题：

1. 任务正常完成后，前端仍保留 `selectedTaskId` 和任务详情，导致任务
   设置区域继续显示刚完成任务的 100% 状态，而不是新任务表单。
2. 暂停任务后修改设置，当前后端会直接应用设置并重启任务，没有让用户
   决定如何处理旧任务成果。前端也没有清晰区分“修改当前任务”和
   “另建新任务”，最终表现为只有手动删除任务后，才能按新设置重新开始。

## 2. 设计目标

- 逐篇和批量任务正常完成后，自动回到新任务创建界面。
- 完成后的任务仍保留在任务中心，可随时查看结果。
- 创建表单完成复位后不保留上一次任务的关键词和其他检索条件。
- 用户修改暂停任务设置时，不会立即重新扫描。
- 保存修改后，由用户明确选择保留或永久删除旧成果。
- 两种成果处理策略都继续使用同一个任务编号，不要求手动删除任务。
- 永久删除必须只作用于当前任务的登记成果，并立即释放磁盘空间。

## 3. 非目标

- 不删除其他任务的文件。
- 不清理任务输出根目录中未登记的未知文件。
- 不保留永久删除文件的回收站副本或隔离副本。
- 不改变关键词、标题精确、全文精确等搜索语义。
- 不绕过登录、验证码或机构额度。
- 本次不修改下载内容格式和数据处理规则。

## 4. 任务完成后的界面复位

只对 `completed` 状态执行自动复位。`failed`、`stopped`、`partial`、
`paused`、`waiting_manual` 等状态保留当前页面。

完成事件触发后，前端执行一次：

1. 清除当前 `selectedTaskId` 和任务详情；
2. 关闭任务设置视图；
3. 回到新任务创建表单；
4. 将表单字段恢复为默认值；
5. 保留任务中心里的任务记录和成果；
6. 保留一条完成提示，并提供“查看刚完成任务”的入口。

默认值：

- 关键词：空字符串；
- 匹配方式：该采集模式的默认检索方式；
- 法规子库：该表单现有默认值；
- 年份：默认全部年份；
- 省份：全部省份；
- 时效性：全部；
- 每页条数：逐篇 20，批量 50；
- 页数选择：默认继续到尾页；
- 批量目录格式：默认 XLSX；
- 全文格式：Word ZIP；
- 输出目录：应用提供的默认逐篇/批量输出目录。

同一个任务只允许触发一次自动复位，避免事件轮询重复清空用户刚开始填写
的新表单。用户之后从任务中心主动打开已完成任务进行查看时，不再自动
跳回创建表单。

## 5. 任务设置修订流程

适用于逐篇和批量采集：

```text
用户暂停任务
  -> 任务保持 paused，不自动打开任务设置
  -> 用户手动点击“任务设置”
  -> 编辑设置
  -> 点击“保存修改”
  -> 后端生成设置修订预览
  -> 用户选择旧成果处理方式
  -> 应用新配置并从第 1 页重新扫描
```

任务没有到达 `paused` 时，不打开可编辑表单，也不写入新配置。用户只点击
“暂停”不会自动打开任务设置，也不会弹出任何成果处理选择。

“保存修改”只生成待确认的修订，不立即重启任务。关闭决策窗口后，任务
保持暂停，已编辑草稿仍在。

## 6. 旧成果处理策略

### 6.1 保留已完成文件并重新扫描

- 保留单篇已下载文件及对应已完成记录。
- 保留批量已验收 ZIP、目录文件和对应已完成批次。
- 删除旧扫描日志、分年计划、结果窗口、待处理项和失败/未完成批次。
- 建立新的配置代次。
- 从第 1 页按新设置重新扫描。
- 已成功完成且能按稳定政策身份匹配的内容不重复下载。

### 6.2 永久删除旧结果并重新扫描

- 永久删除当前任务登记的下载文件、ZIP、目录、处理产物和任务目录中
  已清空的任务专属子目录。
- 删除当前任务的政策条目、批次记录、处理运行记录、任务产物记录和
  旧扫描日志。
- 立即释放磁盘空间，不使用回收站或隔离区。
- 保留任务主记录、任务名称和配置修改历史。
- 建立新的配置代次，并从第 1 页按新设置扫描。

永久删除前必须显示：

- 将删除的政策数量；
- 将删除的文件数量和目录数量；
- 预计释放的字节数；
- 只能删除当前任务成果的说明。

用户必须再次点击红色按钮“确认永久删除并重新扫描”。

## 7. 删除安全边界

删除只处理：

- 当前任务登记的下载文件和任务产物；
- 当前任务输出根目录内的文件；
- 不与另一个任务共享的文件；
- 删除文件后可确认已空且不由其他任务使用的任务专属子目录。

不删除：

- 其他任务登记的文件；
- 与其他任务共享的文件；
- 输出根目录本身；
- 用户后来放入输出目录的未登记文件；
- 数据库文件、日志目录、程序目录或用户主目录。

若存在无法安全永久删除的现有登记文件，则：

- 不应用新设置；
- 不启动新扫描；
- 任务保持暂停；
- 返回 `TASK_OUTPUT_DELETE_BLOCKED`；
- 列出受保护文件及原因。

若删除过程中任一文件删除失败：

- 停止后续提交；
- 保留任务和待确认修订；
- 返回已删除数量、已释放空间和失败文件；
- 不应用新设置，不自动重试。

## 8. 修订预览与提交

### 8.1 预览

新增：

```text
prepareTaskSettingsRevision(
  taskId,
  input,
  outputDir
) -> TaskSettingsRevisionPreview
```

返回内容至少包括：

```json
{
  "token": "opaque token",
  "changed": true,
  "generation": 2,
  "artifactSummary": {
    "completedPolicyCount": 0,
    "completedBatchCount": 0,
    "registeredFileCount": 0,
    "eligibleFileCount": 0,
    "protectedFileCount": 0,
    "directoryCount": 0,
    "estimatedFreedBytes": 0
  },
  "protectedFiles": []
}
```

预览数据写入任务检查点：

```json
{
  "pendingSettingsRevision": {
    "token": "opaque token",
    "baseGeneration": 1,
    "baseUpdatedAt": "ISO-8601",
    "taskInput": {},
    "outputDir": "absolute path",
    "artifactSummary": {},
    "createdAt": "ISO-8601"
  }
}
```

### 8.2 提交

新增：

```text
commitTaskSettingsRevision(
  taskId,
  token,
  artifactPolicy,
  operationId
) -> TaskSettingsUpdateResult
```

`artifactPolicy` 只允许：

- `preserve`
- `delete`

提交前必须校验：

- token 与检查点一致；
- 任务仍是同一配置代次；
- 任务仍处于暂停状态；
- 输出目录和成果数量没有在预览后发生变化；
- 预览中的受保护文件为空，否则不能执行 `delete`。

校验失败返回 `SETTINGS_REVISION_STALE`，要求重新生成预览。

## 9. 状态与交互

- 普通“暂停”操作只改变任务状态，不打开任务设置。
- 任务未暂停时点击“任务设置”，只提示先暂停任务，不自动代为暂停。
- 进入 `paused` 后，用户再次手动点击“任务设置”才打开设置表单。
- 保存修改后显示成果处理对话框。
- 选择保留时，主按钮为“保留结果并重新扫描”。
- 选择永久删除时，先进入确认步骤，最终按钮为
  “确认永久删除并重新扫描”。
- 取消后保留草稿、任务暂停状态和 `pendingSettingsRevision`。
- 提交成功后关闭设置和对话框，任务自动按新配置启动。

## 10. 验收标准

1. 逐篇任务正常完成后自动回到空白创建表单。
2. 批量任务正常完成后自动回到空白创建表单。
3. 完成一次事件循环后表单不会被重复清空。
4. 用户主动打开历史完成任务时仍可查看结果。
5. 失败、停止、暂停和等待人工处理的任务不自动复位。
6. 暂停操作不会自动打开任务设置；未处于 `paused` 状态时不能打开可编辑设置。
7. 保存修改只生成预览，不自动应用或启动。
8. 保留策略不会删除已完成文件，并会清除旧扫描计划后重新扫描。
9. 删除策略会删除任务登记成果，并立即释放空间。
10. 删除失败不改变配置、不启动新任务。
11. 共享文件或其他任务文件永远不会被永久删除。
12. 逐篇与批量都保持原任务编号，不新增重复任务。
