# 北大法宝工作台 0.2.4 启动预检异步化发布与验收

**版本：** 0.2.4

**构建日期：** 2026-11-05

**验收状态：** 通过

## 修复目标

0.2.3 在年份区间较大时，`collector.start` 会同步执行全部零下载预检。
预检可能持续数分钟；在 Python 主请求循环返回之前，任务列表和浏览器状态
请求可能超时。前端因此同时出现“暂无逐篇任务”和“浏览器被任务占用”。

0.2.4 将启动预检迁移到后台工作线程，并在任务记录创建后立即返回。

## 行为变化

- 点击“创建并开始”后任务立即出现在任务区，状态为“启动预检”；
- 预检进度写入 SQLite，包含已完成组合数、总组合数、当前查询和结果数；
- 预检期间任务列表、任务详情和浏览器状态请求不再等待完整预检结束；
- 预检阶段只显示“停止”，不显示此时无法执行的“暂停”；
- 停止预检会在当前安全检索边界取消后续组合，并释放浏览器租约；
- 停止后晚到的预检结果不得把任务重新标为运行或等待状态；
- 预检成功、失败或取消均保留原任务 ID 和结构化错误；
- 逐篇和批量采集共用同一后台预检行为。
