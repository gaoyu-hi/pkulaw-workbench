## 实施内容

- 新增 `engine/pkulaw_engine/catalog_formats.py`；
- API 保留 `xls`、`xlsx`、`html-xls`，内部映射为
  `native-xls`、`derived-xlsx`、`compat-html-xls`；
- 网站原生目录固定使用 `catalogExcel`、BIFF XLS 签名和 `.xls` 后缀；
- 单篇无关的下载事件仍按原规则忽略；
- 只有持有 `batch-catalog` intent 且来源主机匹配时，错误的目录后缀才
  立即返回 `CATALOG_NATIVE_FORMAT_MISMATCH`；
- 原生格式错误事件包含 `intentId`、`downloadId`、实际文件、后缀、
  文件签名、路径、预期契约和恢复建议；
- `BatchTaskManager` 优先消费网站原生 XLS，再派生用户请求的目录格式；
- 派生成功且目录身份通过后才创建 ZIP intent；
- XLSX 使用 openpyxl 生成，全部单元格强制按文本保存；
- HTML-XLS 使用本地 HTML 表格生成，明确标记为兼容格式；
- HTML-XLS 在前置标题/搜索条件行之后定位真实“序号/标题”表头，
  不再把第一行说明文字误当作表头；
- 原生 XLS、派生 XLSX 和 HTML-XLS 均重新执行标题、行数、稳定政策 ID
  身份校验；
- 派生文件先在临时文件中生成和校验，再原子替换目标；失败不覆盖已有
  正式文件；
- 报告和 checkpoint 保存：
  - `native`；
  - `sourceFormat=xls`；
  - `finalFormat`；
  - `converted`；
  - 原生目录与最终目录 SHA-256；
- 批次错误协议新增可选结构化 `details`；
- 批量界面使用“网站原生 XLS”“本地转换 XLSX（源自网站 XLS）”
  和“兼容 HTML-XLS（本地生成）”；
- 批次错误卡可以展开查看结构化恢复信息；
- 阶段 4 本地机构服务按选择结果异步生成真实 BIFF XLS；
- 阶段 4 烟测分别断言原生 XLS、派生 XLSX 和兼容 HTML-XLS 元数据。
