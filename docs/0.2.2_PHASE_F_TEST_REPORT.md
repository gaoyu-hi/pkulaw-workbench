## 实施内容

- 新增 `engine/pkulaw_engine/progress.py`；
- 定义 `ProgressSnapshot`：
  - `overall`；
  - `stage`；
  - `completedUnits`；
  - `totalUnits`；
  - `succeeded`；
  - `failed`；
  - `pendingReview`；
- 单篇进度权重：
  - 预检 5%；
  - 扫描 25%；
  - 逐条下载 65%；
  - 收尾 5%；
- 批量进度权重：
  - 扫描 20%；
  - 目录与校验 20%；
  - ZIP 与校验 30%；
  - 原子发布和登记 30%；
- 数据处理按政策逐条推进，写入、证据、TXT 和完成数量使用同一快照；
- 单篇、批量和数据处理的 checkpoint / summary 保存 `progressSnapshot`；
- TaskStore 返回的 TaskRecord 和 ProcessingRunRecord 透传
  `progressSnapshot`；
- `partial` 终态固定低于 100%，0/3 成功、3 条待核验显示为 99%
  工作进度，并明确“不是 100% 成功”；
- 旧任务缺少统一快照时，界面按现有进度和任务项安全回退；
- TaskStore 对同一阶段、动作、错误码、进度和计数在 2 秒内重复的
  `task.updated` / `data.run.updated` 事件去重；
- 真实阶段、动作、错误码或计数变化会新增事件；
- 数据处理运行事件持久写入任务时间线；
- 前端时间线继续折叠 2 秒内的 `running → waiting_manual → running`
  短暂回弹；
- 时间线保留真实阶段变化，并显示已处理、成功、失败和待核验数量；
- 新增统一 `ProgressSnapshotCard`，用于单篇、批量、数据处理和任务中心；
- 统一错误卡新增：
  - 动作策略；
  - 实际文件；
  - 格式契约；
  - intentId；
  - downloadId；
  - 正文完整性；
  - 可展开并复制的完整错误和断点；
- 下载次数耗尽、批次产物完整性失败等错误继续保持硬停止，不允许
  普通继续；
- 保留暂停、继续、停止、额度硬停止、SearchSession、筛选、
  原生 XLS、正文来源模型和归档删除语义。
