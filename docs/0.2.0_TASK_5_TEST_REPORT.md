原有 `batch.continue` 和 `data.continue` 继续用于自动暂停后的“已处理，继续”。

### 批量安全边界

批量任务只在以下安全原子步骤边界响应暂停或停止：

- 预检完成；
- 检索提交前；
- 结果页读取后；
- 下一页读取前后；
- 当前批次勾选前后；
- 目录下载、真实格式校验和临时文件确认后；
- ZIP 下载、CRC/数量/路径安全和身份映射校验后；
- 当前批次正式文件移动、任务项完成和 SQLite 批次提交后。

批量 checkpoint 保存：

- 当前关键词；
- 当前子库；
- 当前页；
- 当前批次 key 和序号；
- 行范围；
- 当前目录和 ZIP 文件；
- 当前动作；
- 最后一次完成批次。

### 数据处理安全边界

数据处理只在以下安全边界响应暂停或停止：

- 运行初始化完成；
- 当前政策 Word/TXT/证据写入完成；
- 当前政策 SQLite 记录更新完成；
- 当前政策政府官网 HTML/截图证据完成；
- 总目录、Excel 和任务报告生成前后。

数据处理 checkpoint 保存：

- 当前 policy key；
- 当前动作；
- 已完成政策数量；
- 当前输出目录和已完成产物。

暂停期间不写入不完整 TXT、证据或新政策文件。ZIP 下载和 CRC 校验进行中不会截断。

暂停、恢复和停止的请求信号与 SQLite 状态写入在 `TaskControl.condition` 临界区内完成。这样 worker 先写出 `paused` 时，管理线程不会延迟再写出一个旧状态 `pausing`，造成暂停卡死；单篇、批量和数据处理使用同一修复。

### 继续与恢复

手动恢复：

- 批量使用 `batch.resume`；
- 数据处理使用 `data.resume`；
- 恢复前重新核验网页目标绑定、登录、滑块状态和选择器 profile；
- 成功后从 checkpoint 继续，不从头重新关键词检索。

自动暂停：

- 登录使用 `waiting_login`；
- 滑块、页面不稳定和人工处理使用 `waiting_manual`；
- 继续使用原有 `batch.continue` / `data.continue`。

### 界面统一

- 批量采集页显示暂停、继续、停止、重试失败批次和“已处理，继续”；
- 数据处理页显示暂停、继续、停止和“已处理，继续”；
- 任务中心支持批量的暂停、继续、停止和失败重试；
- 统一使用 `pausing`、`paused`、`stopping` 状态和一致的安全步骤提示；
- 手动暂停与自动暂停使用不同文案；
- 暂停、停止和断点显示关键词、子库、页、批次、行范围、当前动作或政策 key。

### 异常恢复

Engine 启动时：

- 把残留单篇/批量活动状态转为 `stopped`；
- 把残留数据处理活动运行转为 `stopped`；
- 错误码统一为 `APPLICATION_INTERRUPTED`；
- 保留原 checkpoint、总结和已完成数量。
