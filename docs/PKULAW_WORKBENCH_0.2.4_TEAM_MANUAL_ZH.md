# 北大法宝政策采集与数据整理工作台 0.2.4 团队使用手册

**版本：** 0.2.4

**适用范围：** Windows 10/11 x64 团队成员的本地单机使用
**编写日期：** 2026-11-05

## 程序定位

北大法宝政策采集与数据整理工作台用于在用户已获授权的北大法宝会话中，
检索中央和地方政策，下载真实 Word 文件或批量目录与 Word ZIP，并继续完成
正文提取、来源记录、总目录生成和任务报告。

0.2.4 继承 0.2.3 阶段 I 的真实站点验收，并修复长时间启动预检造成的界面
假死。正式“碳中和”只读扫描覆盖
19,040 个唯一结果和 111 个分区；真实下载按固定分层样本验收，其中 I-7
完成 2,784 条，I-7S 完成 25 条，I-8S 完成 100 条地方双批次。

0.2.4 本次新增行为已通过 448 个 Python 测试、119 个前端测试、类型检查、
生产构建和 Electron Stage 6 端到端烟测；没有重新执行真实站点大批量下载。

“全量验收”指检索、分页和身份验证覆盖全量结果。未抽中的政策不会下载，
也不应被解释为失败。

## 当前支持范围

程序当前支持以下主流程：

- 中央法规、地方法规、中央+地方分别检索；
- 单篇关键词、全文和精确完整标题检索；
- 批量关键词和全文检索；
- 全部年份、单一年份和年份区间；单年与区间年份可手输，范围为
  1949 年至当前年份；
- 全部省份或单个省份、全部时效性或指定时效性；
- 每页 10、20、50 或 100 条；
- 扫描到真实尾页或设置页数上限；
- 单篇 Word 下载、正文校验和任务断点；
- 批量原生 XLS 目录、Word ZIP、CRC 和稳定身份校验；
- 从原生 XLS 本地转换 XLSX 或兼容 HTML-XLS；
- TXT、CSV、XLSX、HTML 报告和来源证据生成；
- 逐篇精确标题缺失时的显式政府官网补全；
- 任务暂停、继续、停止、重试、恢复、归档和回收站；
- 机构 Session、内置浏览器和 50%–200% 网页缩放；
- 启动诊断、SQLite 完整性检查和便携包运行。

当前不包含：

- WPS、PDF、纯文本、超文本、纯净版五种额外下载格式；
- “保留字段信息”“保留本篇右侧的法宝联想”“保留正文中的法宝联想”
  三项可选开关；
- macOS 或 Linux 版本；
- 多用户共用一个数据库的服务器部署；
- 自动更新、集中账号管理或集中日志平台。

## 运行条件

团队成员需要准备：

- Windows 10 或 Windows 11 x64 电脑；
- 本地可写目录，建议留出至少 10 GB 可用空间；
- 学校机构入口、学校 IP、CARSI 或本人账号的有效访问权限；
- 允许访问北大法宝和必要官方政府网站的网络环境；
- 由团队指定的 0.2.4 便携 ZIP 包。

不应把程序放在只读目录。不要把程序解压到多人共享的同一个
`数据` 文件夹，也不要在 OneDrive 同步过程中运行正在写入的任务。

## 首次安装与启动

1. 将 `北大法宝采集器_Windows便携版_0.2.4_20261105.zip` 解压到本人电脑
   的本地目录。路径可以包含中文和空格。
2. 双击 `启动法宝工作台.cmd`。不要绕过启动器直接双击
   `法宝工作台.exe`。
3. 启动器会分配随机本机调试端口，并把数据目录指向当前发布目录下的
   `数据` 文件夹。
4. 等待应用显示后端已连接。首次启动可能比后续启动稍慢。
5. 打开“设置与诊断”，运行启动预检。
6. 在“总览”顶部保存学校机构名称和授权入口。
7. 在总览右侧自动打开的内置浏览器中完成学校 IP、CARSI 或账号登录。
8. 如出现滑块或验证码，由当前使用者本人完成。

程序不需要目标电脑安装 Python、Node.js 或 Microsoft Word。旧版 `.doc`
正文提取使用随包提供的 antiword。

## 界面结构与主要用途

### 工作台总览

总览顶部是真正可操作的机构工作区，显示机构名称、授权入口、登录状态、
选择器诊断和网页缩放。未配置或未认证时右侧显示浏览器；认证完成后浏览器
自动收起为状态卡。进入逐篇采集或批量采集也从这里开始。

### 内置浏览器与机构登录

内置浏览器负责机构入口、登录、WebContentsView、持久 Session、网页缩放、
下载事件和人工处理状态。

- 侧边栏没有独立“内置浏览器”页面，只在总览和任务运行工作区出现；
- 每个机构配置使用独立 Session；
- 不读取、复制或导出账号密码；
- 不绕过登录、滑块、验证码或机构额度；
- 当前内置网页支持 50%–200% 缩放；
- `Ctrl +`、`Ctrl -`、`Ctrl 0` 可调整或恢复网页缩放；
- 应用外壳保持独立缩放，不随网页变化。

保存机构配置时，入口地址应是实际使用的学校入口或北大法宝直连地址。
机构 Session 失效后，重新登录并运行诊断，不要复用其他人的 Session。

### 逐篇采集

逐篇采集适合精确标题清单、同名政策核对、单条 Word 下载和需要逐条查看
状态的场景。

常用字段：

| 字段 | 推荐填写方式 |
|---|---|
| 关键词或标题 | 每行一条；批量导入时先去重 |
| 匹配方式 | 标题关键词、全文关键词或精确完整标题 |
| 法规子库 | 中央、地方或中央+地方分别检索 |
| 年份 | 全部年份、单年或区间 |
| 省份 | 中央法规隐藏；地方法规显示；中央+地方只用于地方子库 |
| 时效性 | “全部”只记录元数据，不执行时效性过滤 |
| 每页条数 | 10、20、50 或 100 |
| 分页 | 扫描到尾页或设置上限 |
| 输出目录 | 每个项目使用独立目录 |

单篇匹配方式与网站字段必须一一对应：

| 界面选项 | 北大法宝字段 | 匹配方式 | 同名政策 |
|---|---|---|---|
| 关键词 | 标题 | 精确 | 按稳定政策 ID 分别保留 |
| 全文 | 全文 | 精确 | 按稳定政策 ID 分别保留 |
| 精确完整标题 | 标题 | 精确 | 进入人工候选选择 |

页面提交前和页面稳定后都会回读字段。若网站回退到模糊匹配，任务会失败关闭，
不会打开详情、创建下载意图或把模糊结果交给后续数据处理。

单篇和批量的检索条件会作为本机草稿保留。切换到其他页面后再返回时，
关键词、匹配方式、子库、年份、省份、时效性、分页和输出目录不会恢复成
测试默认值。

新建任务的检索框默认完全为空，`value` 和占位文字都不显示示例内容。切换
页面后保留真实草稿。迁移旧本地草稿时只把孤立的“人工智能”产品默认值改
为空；`人工智能\n数据安全`、`碳中和` 等用户真实输入继续保留。

法规子库同时决定省份参数：

- 中央法规隐藏省份控件，检前核验和任务请求固定为“全部省份”；
- 地方法规显示省份控件；
- 中央+地方显示省份控件，但中央子库忽略地方省份，地方子库使用所选省份；
- 旧草稿或旧任务中的“中央法规 + 北京市”会按中央规则归一化，不再触发地方省份筛选。

标准流程：

1. 在总览确认机构已认证、浏览器已绑定且选择器诊断通过。
2. 进入逐篇采集并填写检索条件。
3. 点击唯一的“创建并开始逐篇采集”；任务会立即出现在右侧，状态为“启动预检”。
4. 在 `collector-preflight` 中观察已完成组合数、总组合数、当前年份和结果数。
5. 预检通过后自动进入扫描，在右侧浏览器处理登录、验证码或同名政策。
6. 需要修改条件时打开“任务设置”；应用后使用同一任务 ID 切换配置版本。
7. 完成后进入“数据与报告”生成 TXT、CSV、XLSX 和任务报告。

程序不再要求单独点击“预览（0 下载）”。点击“创建并开始”后，任务内部会
在后台执行真实检索和零下载检前核验，核对组合数、结果数、总页数、结果窗口、
登录状态和选择器，通过后再启动扫描。任务创建、任务列表、浏览器状态读取和
停止操作不会再被长预检请求串行阻塞。核验失败时仍在原任务中等待处理，
不会创建下载。

预检期间只提供“停止”，不提供此时无效的“暂停”。点击“停止”后，程序会在
当前安全检索边界结束，不再执行后续年份组合，并释放浏览器租约；后台线程
不得把已经停止的任务重新标记为运行或等待状态。年份组合较多时预检持续
数分钟属于正常情况，但进度数字应持续更新。

年份模式与省份分成两行，不并列挤在一起。区间模式中，起始和结束年份均
支持手动输入。若请求起点早于当前检索真实可用的最早年份，程序会先读取
网站年份树，再自动使用有效交集；任务详情同时显示请求年份和实际年份。
区间与真实年份完全无交集时失败关闭，单一年份不存在时也不会自动改年份。

创建表单使用固定底部操作栏，在 1536×864 逻辑视口中“创建并开始”始终可见。
表单主体采用紧凑布局，年份、省份和操作区不会依赖外层页面上下滚动。

分页达到上限但结果尚未结束时，程序会等待使用者选择“继续到尾页”或
停止。程序不会把截断结果当成完整结果。

### 批量采集

批量采集适合一次取得一批政策的网站原生目录和 Word ZIP。

关键规则：

- 批量可在关键词和全文两种模式中选择；
- 每批最多 50 条；
- 先读取并校验网站原生目录，再启动 ZIP；
- 目录格式可选择原生 XLS，或从原生 XLS 本地派生的 XLSX、HTML-XLS；
- ZIP 必须通过 CRC、成员数、空文件、重复项、路径穿越和稳定 ID 映射；
- 失败批次保留证据，可单独重试；
- 已完成批次不会因重试被无记录覆盖。

批量关键词对应“标题 + 精确”，批量全文对应“全文 + 精确”。批量不提供
精确完整标题，也不会使用模糊回退。

规模门禁：

- 预计达到 20 页、500 条政策或 5 个批次时，程序要求人工确认；
- 确认前不会创建任务项、批次或下载；
- 中央+地方任务会分别检索和保存上下文；
- 批量输出、目录和 ZIP 与单篇 Word 任务分开。

标准流程：

1. 填写条件并点击“创建并开始批量采集”。
2. 检查中央/地方范围、年份、省份、目录格式和每页条数。
3. 如果出现规模确认，核对预计页数、政策行数和批次数。
4. 确认后开始目录和 ZIP 下载。
5. 在任务中心查看每个批次的目录、ZIP、报告和错误。
6. 完成后在“数据与报告”生成批量数据处理结果。

### 验证码自动恢复

程序只检测人工操作结果，不识别或绕过验证码。任务等待登录或验证码时，
左栏显示等待、观察、核验、恢复和失败状态，浏览器始终可见。

- 登录页和验证码至少连续三次稳定消失，观察覆盖约 2.5 秒；
- 短暂残留的覆盖层继续观察，不会立即结束工作线程；
- 复核遇到 `CAPTCHA_VISIBLE` 时回到观察状态，不会立刻判定永久失败；
- 页面、登录状态和选择器复核通过后，自动恢复最初等待的同一任务；
- 浏览器租约已释放的检前等待，使用任务 checkpoint 中的恢复上下文确认身份；
- 同名版本、分页上限、批量规模、机构额度和正文完整性仍由人工决策；
- 自动恢复失败后先等待稳定宽限期；宽限期结束才显示唯一的“重新检测并继续”；
- 点击该按钮只重新开始稳定检测，不会强制跳过验证码。

### 任务设置与一屏边界

运行中的单一任务只显示“任务设置”，不再显示“新建任务”。打开设置时
浏览器收起；关闭不改任务，应用差异时才进入安全停止和同任务版本切换。

修改条件后：

- 配置世代递增；
- 旧扫描日志、页数和检前快照不作为新配置起点；
- 未完成的旧条目和批次从新版本派生中隔离；
- 已完成条目、已完成批次和文件记录保留；
- 不会悄悄新建第二个同名任务。

1536×864 逻辑视口下，任务进度和浏览器左右同屏，外层应用不出现上下滚动。
左侧固定显示必要状态、停止主因、进度和主动作，其余运行详情在左侧面板
内部受控滚动；完整条目、长日志和低层诊断留在任务中心或展开详情。内置
浏览器保留网页自身的上下、左右滚动和 50%–200% 缩放。

同一时刻只显示一个继续类主动作。工作线程仍等待人工处理时显示“已处理，
继续”；工作线程已退出但存在可信断点时显示“从断点继续扫描”；恢复失败
宽限期结束后显示“重新检测并继续”。年份不可用、页面结构硬停止、机构额度
等错误不会显示普通继续。

任务停止后，运行面板上部显示唯一主因和“查看停止原因”按钮。单击即可
打开完整详情，同时自动隐藏 Electron 内置浏览器，避免原生网页层覆盖弹窗；
关闭详情后浏览器恢复。弹窗包含用户可理解的摘要、下一步、错误代码、当前
组合、页码、断点、可用年份或候选值和原始错误。

主动作点击后顶部状态区先显示“正在处理”，结束前显示成功或明确失败原因。
反馈不依赖面板底部，不需要通过外层滚动寻找。

### 任务中心

任务中心是整个任务生命周期的统一入口。

可以执行：

- 按模式、状态和关键词筛选任务；
- 查看每个任务项或批次的当前阶段；
- 查看错误码、断点、来源、下载意图和下载 ID；
- 人工暂停、继续、停止和失败重试；
- 选择同名政策的具体版本；
- 处理分页上限和批量规模确认；
- 查看任务时间线和失败原因；
- 打开输出目录和最新产物；
- 归档任务；
- 将数据库登记文件移入 Windows 回收站；
- 在明确确认后永久删除任务记录。

任务停止后应保留 `数据` 文件夹和断点。重新启动同一任务前，核对检索条件
没有改变。完成项和已存在文件会被跳过，未完成项从可信断点继续。

### 数据与报告

数据处理用于把已经取得真实来源的任务整理成可交付资料。

当前生成：

- 逐条 UTF-8 TXT；
- 总目录 CSV；
- 总目录 XLSX；
- HTML 任务报告；
- 来源证据 JSON；
- Word 原件和必要的政府官网 HTML、PNG 证据；
- 正文来源、提取方法、转换器名称和版本；
- 正文完整性、核验状态和 SHA-256。

数据处理只选择具有真实 Word、批量 ZIP 成员或明确政府官网来源的项目。
`pending`、`skipped` 和一般失败项不会自动生成伪造的派生文档。

### 设置与诊断

诊断页检查：

- 应用版本和后端版本；
- Python 内置运行时；
- DrissionPage、python-docx、openpyxl 和 xlrd；
- SQLite schema 和完整性；
- 数据、日志、下载临时目录和系统临时目录；
- 机构入口网络；
- 内置浏览器绑定和选择器；
- 显示缩放；
- antiword 转换器；
- 磁盘空间；
- 网页 Session 和缩放状态。

遇到异常时先运行诊断，再检查浏览器页面和任务错误。不要先删除数据库、
断点或暂存文件。

## 输出目录与文件说明

便携启动器使用程序目录下的 `数据` 文件夹。典型结构如下：

```text
数据/
  pkulaw.sqlite3
  logs/
  downloads/
    staging/
  single-word/
    processed/
      01_来源Word/
      02_正文TXT/
      03_政府官网正文整理/
      04_来源证据/
      05_待核验/
      06_总目录.csv
      06_总目录.xlsx
      07_任务报告.html
  batch-files/
    地方法规/
    中央法规/
```

`01_来源Word` 按中央或地方库归档真实 Word。`02_正文TXT` 保存提取后的
UTF-8 正文。`04_来源证据` 保存来源 URL、检索时间、文件哈希、正文质量
和转换器信息。`05_待核验` 只保存有证据支持的异常，不表示批量成功。

发布 ZIP 本身不包含个人 `数据`。任务完成后，如果要把结果交给其他成员，
优先交付该项目的输出目录、CSV、XLSX、HTML 报告和证据，而不是整个
应用数据目录。

## 账号 Session 与机构额度

- 账号和密码由使用者本人输入；
- 程序不保存密码；
- 程序不导出 Cookie；
- 不把 Session 文件夹复制给其他成员；
- 不共享登录二维码、验证码结果或机构账号；
- 同一学校 IP 的正文查看和下载额度可能由多人共同消耗；
- 任务出现额度提示后应停止扩大请求，等待授权恢复或联系机构管理员；
- 程序不会通过换 Cookie、伪造身份或绕过滑块解决额度问题。

## 数据保留与备份

推荐在每次正式任务前备份 SQLite，在任务完成后备份整个项目输出。

备份步骤：

1. 停止所有任务并正常关闭应用。
2. 等待 Electron 和 Python 进程退出。
3. 复制整个 `数据` 文件夹到独立备份目录。
4. 对备份中的 `pkulaw.sqlite3` 运行诊断或完整性检查。
5. 记录应用版本、任务 ID、输出目录和 ZIP SHA-256。

不要在应用运行中直接复制 SQLite 和 WAL 文件作为唯一备份。若必须在线备份，
应同时保留 `pkulaw.sqlite3`、`-wal` 和 `-shm` 文件。

## 常见错误与处理

| 错误或现象 | 含义 | 处理方式 |
|---|---|---|
| 后端未连接 | Python 后端未就绪或退出 | 正常关闭应用，使用启动器重开，再运行诊断 |
| 页面选择器不匹配 | 当前页面不是预期检索页，或站点页面变化 | 回到北大法宝检索页并重新诊断，不要强行启动 |
| 登录失效 | Session 不再有效 | 由使用者本人在内置浏览器重新登录 |
| 验证码或滑块可见 | 需要人工验证 | 本人完成后等待三次稳定检测；短暂残留继续观察；宽限期后失败才显示“重新检测并继续” |
| `INSTITUTION_QUOTA_REACHED` | 机构访问或正文额度限制 | 停止任务，保留断点，联系机构确认恢复 |
| `PAGE_LIMIT_REACHED` | 达到配置页数上限 | 核对当前结果后选择继续到尾页或停止 |
| `BATCH_SCALE_CONFIRMATION_REQUIRED` | 批量规模超过确认阈值 | 核对页数、行数和批次数后确认或停止 |
| `YEAR_FILTER_UNAVAILABLE` / `YEAR_RANGE_UNAVAILABLE` | 年份树不可用或请求区间与真实年份无交集 | 查看完整原因并调整年份；不要期待普通继续放行 |
| `DOWNLOAD_UNCLEAR` | 点击后未收到可信下载事件 | 保留断点，检查额度和页面；不要重复点击刷下载 |
| `BODY_INCOMPLETE` | 正文缺章、缺条或尾部异常 | 在待核验中查看原始证据；修复后重试受影响项 |
| `SOURCE_WORD_MISSING` | 任务记录没有可处理的真实 Word | 检查来源任务和文件是否存在，不伪造派生文件 |
| `ZIP` 身份映射失败 | ZIP 成员和目录无法唯一对应 | 保留批次证据和原始文件，修复映射后重试 |
| 文件路径过长 | Word 工具无法打开长路径 | 当前版本会使用短临时路径；仍有问题可将项目放到较短根目录 |

## 团队使用方式

建议为每名成员提供独立的便携 ZIP 和独立本地数据目录。

- 资料负责人负责检索条件和样本确认；
- 任务操作人负责登录、现场验证码和任务控制；
- 审核人负责抽查 CSV、XLSX、TXT、来源证据和 SHA-256；
- 管理员负责版本、SHA-256、备份和机构额度协调。

首次团队试用建议从一名操作人、一个小查询和一个明确输出目录开始。确认
登录、启动预检、预检停止、断点恢复、数据处理和备份都正常后，再扩大到多成员。

不要在同一学校 IP 上同时启动多个大规模任务。多人并行下载会加快额度消耗，
也会让故障归属更难判断。

## 交付前检查清单

- 使用官方发布的 0.2.4 便携 ZIP；

- 等待零下载核验通过并自动进入运行；
- 小规模试跑并人工检查输出；
- 记录任务 ID 和输出目录；
- 任务完成后备份 `数据`；
- 正常退出并确认没有残留进程；
- 不把含真实 Session、日志和成果的 `数据` 目录上传到 GitHub 或群共享。
