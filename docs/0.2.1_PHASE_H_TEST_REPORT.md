## 完成内容

### CSV/XLSX 输出安全

- 新增 `spreadsheet_safe_text()`、`csv_safe_text()` 和
  `xlsx_safe_text()`；
- CSV 对 `=`、`+`、`-`、`@`，以及前置空格、tab、CR、LF 后的
  同类文本添加单引号安全前缀；
- CSV 保留完整正文，包括超过 Excel 单元格上限的文本；
- XLSX 不添加单引号，而是保留可读原值并将单元格强制写为文本类型；
- 超过 Excel 32767 字符上限的 XLSX 单元格截断到安全长度，并以
  `…[完整内容见CSV]` 明确标记；
- CSV、XLSX 和任务报告使用临时文件生成；
- 数据处理产物全部生成和复核后，使用
  `atomic_replace_many()` 成组替换正式文件；
- 发布后复核失败时恢复替换前的正式文件。

### ZIP 资源限制与成员名安全

- 新增 `ArchiveLimits`：
  - 最大压缩包字节数；
  - 最大总解压大小；
  - 最大单成员大小；
  - 最大成员数；
  - 最大压缩比；
  - 最大目录深度；
  - 最大成员名长度；
- 文件成员和目录成员均检查路径与名称；
- 拒绝：
  - Windows 保留名，包括 `CON`、`NUL`、`COM1` 等；
  - Windows 非法字符；
  - 尾随点和空格；
  - 大小写不敏感重复成员；
  - 绝对路径、盘符路径和 `..` 路径穿越；
  - 过深目录和过长成员名；
- 完成限制检查后才执行 CRC 校验和全文身份映射。

### 批次目录原子发布

- 新增 `engine/pkulaw_engine/atomic_publish.py`；
- 批次文件先复制到独立 `.publishing` 目录；
- 每个文件记录大小和 SHA-256；
- 业务报告保持为可直接读取的 `验收报告.json`；
- 文件清单单独保存为 `_publish_manifest.json`；
- 清单校验通过后将整个批次目录一次移动到正式目录；
- 正式目录已存在且清单有效时直接恢复数据库登记，不重新下载；
- 正式目录存在但清单、文件大小或哈希无法核验时拒绝覆盖；
- 清单路径、重复名称、报告载荷、文件大小和 SHA-256 均在恢复时复核；
- 批次登记在单个 SQLite 事务中完成；
- `batch.batch-completed` 事件发送失败不会回滚已提交的批次记录。

### 已登记批次失败关闭

- 已完成批次启动前重新校验：
  - SQLite 登记的三条路径是否仍在同一正式目录；
  - 发布清单是否存在且可解析；
  - 清单文件与正文、目录、报告是否一致；
  - 每个文件大小和 SHA-256；
  - SQLite 登记路径是否属于发布清单；
  - 报告载荷中的政策 ID 是否与批次记录一致；
- 文件缺失返回 `BATCH_ARTIFACT_MISSING`；
- 路径不一致返回 `BATCH_ARTIFACT_PATH_MISMATCH`；
- 哈希或清单异常返回 `BATCH_ARTIFACT_INTEGRITY_MISMATCH`；
- SQLite 与清单不一致返回 `BATCH_ARTIFACT_DATABASE_MISMATCH`；
- 上述异常均标记批次失败并停止消费，不自动覆盖正式目录。

### 数据处理 artifact 一致性

- `complete_task_batch_atomic()` 在单事务中更新批次、任务项和事件；
- `replace_task_artifacts_atomic()` 在单事务中替换处理运行 artifact；
- 数据处理发布后要求恰好登记 3 个 artifact：
  - 总目录 CSV；
  - 总目录 XLSX；
  - 任务报告 HTML；
- 每个 artifact 均要求：
  - 文件存在；
  - SQLite 中保存 SHA-256；
  - 实际文件 SHA-256 与登记值一致；
  - 报告 HTML 中引用的 CSV/XLSX 哈希与实际文件一致。

## 故障注入覆盖

- 目录或 ZIP 校验失败时，不创建正式批次目录；
- 批次文件已进入 staging、正式移动前失败时，仅保留 staging；
- 正式目录已移动、SQLite 提交前失败时，重试从发布清单恢复；
- 已完成批次文件缺失、被篡改或 SQLite 路径不一致时失败关闭；
- 发布目录有效但数据库尚未登记时，重启不重复下载；
- SQLite 已提交、完成事件发送失败时，持久化批次保持完成；
- CSV/XLSX/报告发布后复核失败时，旧正式文件全部恢复；
- 正式目录已存在且被篡改时，新 staging 不覆盖原目录；
- 重复原子替换目标、大小写重复发布名和清单路径穿越均被拒绝。
